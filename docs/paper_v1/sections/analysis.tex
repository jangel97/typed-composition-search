\section{Analysis}
\label{sec:analysis}

\subsection{Error Profile}
\label{sec:regressions}

We observe 50 query instances across all model--domain combinations where the baseline achieves non-zero recall while TCR achieves zero.
All regressions originate from incorrect entity type predictions: graph search either finds no valid path or follows a wrong path.

This reflects a shift in error profile rather than simply fewer errors.
The baseline produces both false positives (hallucinated tools, invalid compositions) and false negatives (missing tools).
The typed decomposition structurally eliminates hallucinations and invalid compositions; remaining errors arise only from incorrect entity predictions.
Average precision increases from 0.48 to 0.88 (+83\%), while recall increases more modestly from 0.67 to 0.83, consistent with the typed decomposition primarily reducing false positives.

Whether this conservative failure mode is desirable depends on the application: in safety-critical domains, returning no result may be preferable to invoking incorrect tools.

\subsection{Model Effect}
\label{sec:model-effect}

The smaller models evaluated in this study benefit more from the typed decomposition than the larger models.
Granite-8B averages $\Delta$F1 = +0.365 across domains, whereas Qwen3-14B averages +0.264.

Because this comparison involves only four models, we interpret it as preliminary evidence that graph constraints may compensate for weaker tool-selection ability rather than a general scaling law.

\subsection{Task Difficulty}
\label{sec:task-difficulty}

Across all 589 query instances, the LLM correctly predicts both entity types in 61\% of cases, compared to only 12\% where the baseline achieves perfect tool selection (F1 = 1.0).
When direct tool selection fails, entity prediction still succeeds 60\% of the time (range: 54--63\% across models), suggesting that the decomposition presents the model with a more tractable prediction task (Figure~\ref{fig:task-difficulty}).
Although the two metrics are not directly comparable---perfect tool selection requires an exact multi-step sequence while entity prediction requires two correct labels---the consistently higher accuracy across all models supports this interpretation.

\subsection{Why the Decomposition Helps}
\label{sec:mechanistic}

The improvements arise from three complementary mechanisms.
First, TCR shifts prediction from the tool catalog to the entity type space, which entity pruning further reduces by 56--87\% (Section~\ref{sec:entity-pruning}).
Second, graph search constrains the output to compositionally valid paths, exposing only 1.4--2.0 candidate tools per query instead of the full registry of 54--170 tools.
Third, every returned workflow is structurally valid by construction (Proposition~1), eliminating hallucinated tool invocations entirely (Table~\ref{tab:hallucinations}).
These reductions are determined by graph topology and apply independently of the language model used for type prediction.

\subsection{Fault Tolerance}
\label{sec:fault-tolerance}

The recall decomposition (Section~\ref{sec:recall-decomposition}) shows that TCR degrades gracefully under entity prediction errors rather than failing catastrophically.
Across all model--domain combinations, $R_{\text{wrong}}$ remains consistently above zero (0.10--0.65), indicating that incorrect type predictions frequently recover part of the correct workflow.

This behavior emerges naturally from graph topology.
Neighboring entity types often share downstream paths, allowing graph search initiated from an incorrect but nearby entity to traverse portions of the same workflow.

To quantify this relationship, we measure the average number of entity types that can reach a given target through valid graph paths (average reverse reachability).
This metric captures local connectivity: domains where more source types connect to each target provide more opportunities for partial recovery under wrong predictions.

\begin{figure}[t]
\centering
\includegraphics[width=\columnwidth]{figures/scatter_reachability_vs_rwrong.pdf}
\caption{Graph reachability (average reachable sources per target) vs.\ $R_{\text{wrong}}$ across all 20 model--domain combinations. Pearson $r = 0.68$, $p = 0.001$, $R^2 = 0.46$. Domains with richer connectivity exhibit greater fault tolerance. Colors indicate domains; marker shapes indicate models.}
\label{fig:reachability-vs-rwrong}
\end{figure}

Figure~\ref{fig:reachability-vs-rwrong} confirms a strong positive correlation between graph reachability and $R_{\text{wrong}}$ (Pearson $r = 0.68$, $p = 0.001$, $R^2 = 0.46$).
GitHub, the most connected domain (10.2 reachable sources per target), achieves the highest average $R_{\text{wrong}}$ (0.48), while Kubernetes, the sparsest (3.4), achieves the lowest (0.18).
This correlation holds across all four models, indicating that fault tolerance is a property of the graph topology rather than of any particular language model.
