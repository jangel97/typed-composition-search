\section{Related Work}
\label{sec:related-work}

Existing work on tool use by language models can be broadly grouped into three directions: direct tool selection, graph-based planning, and compositional reasoning agents.

\paragraph{Direct Tool Selection.}

Most tool-routing systems formulate the problem as selecting one or more tools directly from a catalog.
ToolLLM~\cite{qin2024toolllm}, Gorilla~\cite{patil2024gorilla}, and Toolformer~\cite{schick2023toolformer} train or adapt language models to decide when and how to invoke APIs.
ToolBench~\cite{xu2023toolbench} and API-Bank~\cite{li2023apibank} provide evaluation frameworks for tool manipulation capabilities, while ToolScope~\cite{li2025toolscope} studies embedding-based retrieval as a scalable alternative for large tool collections.
TaskBench~\cite{shen2024taskbench} introduces a tool graph for benchmark generation, though the graph is used to construct evaluation data rather than for runtime routing.

These approaches reason directly over tools, framing routing as a retrieval or classification problem in the tool space.
In contrast, Typed Composition Routing shifts semantic prediction from tools to entity types and delegates tool composition to graph search, separating semantic reasoning from structural reasoning rather than requiring the language model to solve both simultaneously.

\paragraph{Graph-Constrained Tool Planning.}

Several recent works incorporate graph structure into tool planning.
ControlLLM~\cite{zhang2024controlllm} constructs a tool dependency graph and searches for valid multimodal pipelines.
PLaG~\cite{lin2024plag} serializes task graphs into prompts to guide language models during planning.

Our approach differs in both objective and complexity.
Rather than performing task decomposition, scheduling, or workflow optimization, Typed Composition Routing performs only two steps: entity type prediction followed by deterministic graph search over a typed composition graph.
The resulting system is substantially simpler while still providing structural guarantees on tool composition.

Graph-native learning methods such as GNN4Plan~\cite{wang2024gnn4plan}, GRAFT~\cite{li2025graft}, and GAP~\cite{li2025gap} learn graph-aware planning through supervised learning or reinforcement learning.
These approaches achieve strong planning performance but require task-specific training data and model optimization.
Typed Composition Routing instead operates with off-the-shelf language models and requires no additional training, making it complementary to learned graph planners rather than a replacement.

\paragraph{Compositional Reasoning Agents.}

General-purpose agent frameworks such as HuggingGPT~\cite{shen2023hugginggpt}, Chameleon~\cite{lu2023chameleon}, and ReAct~\cite{yao2023react} rely primarily on language-model reasoning to compose multi-step tool invocations.
While highly flexible, these systems provide no explicit structural guarantees that generated tool sequences are compositionally valid.

Typed Composition Routing augments language-model reasoning with an explicit typed graph.
The language model predicts semantic intent through entity types, while graph search guarantees that every returned workflow satisfies the typing constraints encoded in the graph.

\paragraph{Positioning.}

Table~\ref{tab:positioning} summarizes the design space.
Retrieval-based approaches require neither graph structure nor training but provide no compositional guarantees.
Graph-native learning approaches provide strong structural reasoning but require supervised training or reinforcement learning.
Typed Composition Routing combines structural guarantees with zero additional training by separating semantic prediction from graph-constrained composition.
