\section{Analysis}
\label{sec:analysis}

\subsection{Failure Analysis}
\label{sec:failure-analysis}

The oracle strategy achieves F1 = 1.000 across all five domains, demonstrating that every benchmark workflow is representable in the typed composition graph.
Under the current graph construction, every observed end-to-end routing failure therefore originates from incorrect entity type prediction rather than graph incompleteness.

Once the correct source and target entity types are identified, graph search deterministically recovers the correct tool sequence.
Within this benchmark, future improvements are therefore more likely to come from improving entity type prediction than from expanding graph coverage.

\subsection{Regression Analysis}
\label{sec:regressions}

Across all model--domain combinations, we observe 50 query instances where the baseline achieves non-zero recall while graph routing achieves zero.
Inspection shows that all regressions originate from incorrect source or target entity predictions.
When type prediction fails, graph search either finds no valid path or follows a path corresponding to the wrong entity types.

This behavior reflects a conservative failure mode rather than a compositional failure.
Instead of producing structurally invalid tool sequences, graph routing abstains from execution when the predicted entity types cannot support the desired workflow.

Whether this tradeoff is desirable depends on the application.
In safety-critical domains such as infrastructure automation or financial systems, returning no tool sequence may be preferable to invoking incorrect tools.
Applications emphasizing exploration or recall may instead tolerate structurally invalid suggestions in exchange for higher coverage.

\subsection{Model Effect}
\label{sec:model-effect}

The smaller models evaluated in this study benefit more from graph routing than the larger models.
Granite-8B averages $\Delta$F1 = +0.365 across domains, whereas Qwen3-14B averages +0.264.

This observation is consistent with the hypothesis that structural constraints compensate for weaker semantic reasoning by reducing the effective decision space presented to the language model.
Because this comparison involves only four evaluated models, we interpret it as preliminary evidence rather than a general scaling law.

\subsection{Mechanistic Explanation}
\label{sec:mechanistic}

The experimental results suggest three complementary mechanisms that explain the observed improvements.

\paragraph{Semantic Reduction.}

Typed Composition Search asks the language model to predict entity types rather than executable tools.
The prediction problem is therefore expressed over the entity space instead of the tool catalog.
Entity pruning (Section~\ref{sec:entity-pruning}) further reduces this space by eliminating unreachable source entities once the target type is known.
Across domains, 56--87\% of entity types are removed before source prediction.
This reduction is entirely determined by graph topology and is independent of model quality.

\paragraph{Structural Reduction.}

Graph search transforms semantic predictions into executable workflows.
Rather than considering arbitrary tool combinations, breadth-first search explores only compositionally valid paths connecting the predicted entity types.
The effective decision space is therefore reduced from the entire tool catalog to the small set of tools lying on valid graph paths.
In practice, each query exposes only 1.4--2.0 candidate tools instead of the full registry of 54--170 tools.

\paragraph{Execution Guarantees.}

Every workflow returned by graph routing is compositionally valid by construction.
Adjacent tools always compose because graph edges encode compatible input and output entity types.
Consequently, graph routing cannot hallucinate tool invocations outside the registered tool graph.
This structural guarantee is absent from direct tool selection.

Taken together, these mechanisms provide a plausible explanation for the observed improvements.
Semantic reasoning is performed by the language model through entity prediction, structural reasoning is delegated to graph search, and execution is limited to compositionally valid workflows.
Rather than reasoning directly over the complete tool catalog, the model reasons over entity types while the graph enforces workflow validity.

\subsection{Fault Tolerance}
\label{sec:fault-tolerance}

The recall decomposition (Section~\ref{sec:recall-decomposition}) shows that graph routing degrades gracefully under entity prediction errors rather than failing catastrophically.
Across all model--domain combinations, $R_{\text{wrong}}$ remains consistently above zero (0.10--0.65), indicating that incorrect type predictions frequently recover part of the correct workflow.

This behavior emerges naturally from graph topology.
Neighboring entity types often share downstream paths, allowing graph search initiated from an incorrect but nearby entity to traverse portions of the same workflow.
Domains with richer local connectivity therefore exhibit greater resilience to prediction errors than sparser domains.
For example, GitHub achieves an average $R_{\text{wrong}}$ of 0.48, substantially higher than less connected domains.

Robustness therefore depends not only on entity prediction accuracy but also on graph topology.
Improving the organization of the typed composition graph can increase error tolerance even without improving the underlying language model.
