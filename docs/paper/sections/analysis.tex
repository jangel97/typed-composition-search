\section{Analysis}
\label{sec:analysis}

\subsection{Failure Analysis}
\label{sec:failure-analysis}

The oracle strategy achieves F1 = 1.000 across all five domains, demonstrating that every benchmark workflow is representable in the typed composition graph.
Under the current graph construction, every observed end-to-end routing failure therefore originates from incorrect entity type prediction rather than graph incompleteness.

Once the correct source and target entity types are identified, graph search deterministically recovers the correct tool sequence.
Within this benchmark, future improvements are therefore more likely to come from improving entity type prediction than from expanding graph coverage.

\subsection{Regression Analysis}
\label{sec:regressions}

Across all model--domain combinations, we observe 50 query instances where the baseline achieves non-zero recall while graph routing achieves zero.
Inspection shows that all regressions originate from incorrect source or target entity predictions.
When type prediction fails, graph search either finds no valid path or follows a path corresponding to the wrong entity types.

This behavior reflects a shift in error profile rather than simply fewer errors.
The baseline produces both false positives (hallucinated tools, incorrect selections, invalid compositions) and false negatives (missing required tools).
Graph routing structurally eliminates hallucinated tools and invalid compositions; the remaining false positives arise only from valid-but-wrong graph paths caused by incorrect entity predictions.
False negatives are similarly concentrated: they occur when incorrect type predictions lead to no valid path or to a path that omits required tools.

This shift is reflected in the aggregate metrics.
Average precision increases from 0.48 (baseline) to 0.88 (graph), an 83\% relative improvement, while average recall increases more modestly from 0.67 to 0.83.
These results are consistent with graph routing substantially reducing false positives---an expected consequence of constraining outputs to valid graph paths---while also improving recall through the structured decomposition of the routing task.

Whether the conservative failure mode is desirable depends on the application.
In safety-critical domains such as infrastructure automation or financial systems, returning no tool sequence may be preferable to invoking incorrect tools.
Applications emphasizing exploration or recall may instead tolerate structurally invalid suggestions in exchange for higher coverage.

\subsection{Model Effect}
\label{sec:model-effect}

The smaller models evaluated in this study benefit more from graph routing than the larger models.
Granite-8B averages $\Delta$F1 = +0.365 across domains, whereas Qwen3-14B averages +0.264.

Because this comparison involves only four models, we interpret it as preliminary evidence that graph constraints may compensate for weaker tool-selection ability rather than a general scaling law.

\subsection{Mechanistic Explanation}
\label{sec:mechanistic}

The experimental results suggest three complementary mechanisms that explain the observed improvements.

\paragraph{Semantic Reduction.}

Typed Composition Routing asks the language model to predict entity types rather than executable tools.
The prediction problem is therefore expressed over the entity space instead of the tool catalog.
Entity pruning (Section~\ref{sec:entity-pruning}) further reduces this space by eliminating unreachable source entities once the target type is known.
Across domains, 56--87\% of entity types are removed before source prediction.
This reduction is entirely determined by graph topology and is independent of model quality.
The type prediction accuracies reported in Table~\ref{tab:type-prediction} reflect this simplified prediction task.

\paragraph{Structural Reduction.}

Graph search transforms semantic predictions into executable workflows.
Rather than considering arbitrary tool combinations, graph search explores only compositionally valid paths in the typed composition graph connecting the predicted entity types.
In practice, each query exposes only 1.4--2.0 candidate tools instead of the full registry of 54--170 tools (Table~\ref{tab:entity-pruning}).
Beyond reducing the decision space, graph topology also provides fault tolerance: when type predictions are incorrect, richer graph connectivity allows partial recovery of the correct workflow (Section~\ref{sec:fault-tolerance}).

\paragraph{Execution Guarantees.}

Every workflow returned by graph routing is compositionally valid by construction (Proposition~1).
Consequently, graph routing cannot hallucinate tool invocations outside the registered tool graph.
Table~\ref{tab:hallucinations} confirms this across all model--domain combinations.

\subsection{Fault Tolerance}
\label{sec:fault-tolerance}

The recall decomposition (Section~\ref{sec:recall-decomposition}) shows that graph routing degrades gracefully under entity prediction errors rather than failing catastrophically.
Across all model--domain combinations, $R_{\text{wrong}}$ remains consistently above zero (0.10--0.65), indicating that incorrect type predictions frequently recover part of the correct workflow.

This behavior emerges naturally from graph topology.
Neighboring entity types often share downstream paths, allowing graph search initiated from an incorrect but nearby entity to traverse portions of the same workflow.

To quantify this relationship, we measure the average number of entity types that can reach a given target through valid graph paths (average reverse reachability).
This metric captures local connectivity: domains where more source types connect to each target provide more opportunities for partial recovery under wrong predictions.

\begin{figure}[t]
\centering
\includegraphics[width=\columnwidth]{figures/scatter_reachability_vs_rwrong.pdf}
\caption{Graph reachability (average reachable sources per target) vs.\ $R_{\text{wrong}}$ across all 20 model--domain combinations. Pearson $r = 0.68$, $p = 0.001$, $R^2 = 0.46$. Domains with richer connectivity exhibit greater fault tolerance. Colors indicate domains; marker shapes indicate models.}
\label{fig:reachability-vs-rwrong}
\end{figure}

Figure~\ref{fig:reachability-vs-rwrong} confirms a strong positive correlation between graph reachability and $R_{\text{wrong}}$ (Pearson $r = 0.68$, $p = 0.001$, $R^2 = 0.46$).
GitHub, the most connected domain (10.2 reachable sources per target), achieves the highest average $R_{\text{wrong}}$ (0.48), while Kubernetes, the sparsest (3.4), achieves the lowest (0.18).
This correlation holds across all four models, indicating that fault tolerance is a property of the graph rather than of any particular language model.

Together with the type prediction correlation reported in Section~\ref{sec:recall-decomposition}, these results provide complementary evidence for the two factors identified by the recall decomposition: entity prediction quality determines how often the correct path is found ($r = 0.71$ with F1), while graph topology determines how much is recovered when it is not ($r = 0.68$ with $R_{\text{wrong}}$).
