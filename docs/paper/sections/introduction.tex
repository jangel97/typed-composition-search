
\section{Introduction}
\label{sec:introduction}

Large Language Model (LLM) agents increasingly rely on external tools to answer questions and perform real-world tasks \cite{yao2023react, shen2024hugginggpt}. Modern tool ecosystems routinely contain tens or hundreds of APIs spanning cloud platforms, software development, infrastructure automation, and enterprise operations. As these ecosystems grow, \emph{tool routing} (determining which tools should be invoked to satisfy a user query) becomes increasingly challenging.

Existing approaches typically formulate routing as \emph{direct tool selection}: given a natural language query, the LLM selects tools directly from the full catalog \cite{li2025toolscope, qin2023toolllm}. This formulation requires the model to simultaneously identify relevant tools, infer multi-step compositions, and ensure that the resulting sequence is executable, all in a single unconstrained decision. As tool catalogs grow, this reasoning problem becomes increasingly difficult and may result in missed tool compositions or structurally invalid tool invocations.

We argue that the primary bottleneck is not merely the number of available tools, but the \emph{abstraction} itself. Direct tool routing conflates two fundamentally different reasoning tasks:

\begin{itemize}
    \item \textbf{Semantic reasoning:} What entities does the user refer to?
    \item \textbf{Compositional reasoning:} Which sequence of tool transformations connects those entities?
\end{itemize}

Treating both problems as a single prediction forces the LLM to reason simultaneously about meaning and execution.

We propose \textbf{Typed Composition Routing}, a reformulation of tool routing that explicitly separates these two reasoning problems (Figure~\ref{fig:approach}). Tools are modeled as typed transformations between entity types (e.g., \texttt{get\_pod\_logs}: \texttt{Pod} $\rightarrow$ \texttt{PodLogs}), forming a directed graph where entity types are nodes and tools are edges. Given a user query, the LLM predicts the source and target entity types, after which graph search deterministically recovers the corresponding tool composition.

This decomposition shifts the LLM from selecting executable tools to predicting semantic entities, while delegating composition to a deterministic graph algorithm. Rather than asking the model to discover valid workflows directly, Typed Composition Routing asks it to identify the entities involved, allowing the graph to recover the execution path.

We evaluate the proposed formulation across multiple language models, tool ecosystems, and routing strategies spanning a diverse collection of enterprise domains. Our experiments demonstrate consistent improvements over direct tool selection while providing a simple analytical decomposition that explains end-to-end routing performance in terms of entity prediction accuracy and graph resolution.

Our contributions are:

\begin{enumerate}

\item \textbf{Problem reformulation.}
We reformulate tool routing as typed entity reasoning, shifting the LLM's responsibility from direct tool selection to entity type prediction.

\item \textbf{Typed graph execution model.}
We introduce a deterministic execution model that combines entity prediction with graph search to recover valid tool compositions without training, fine-tuning, or embedding retrieval.

\item \textbf{Analytical decomposition.}
We show that end-to-end routing recall decomposes into entity prediction accuracy and graph reachability, enabling targeted analysis of routing failures.

\item \textbf{Comprehensive benchmark.}
We evaluate four language models across five tool domains, six routing strategies, and 140 benchmark queries covering multiple routing difficulty categories.

\item \textbf{Empirical validation.}
We demonstrate that Typed Composition Routing consistently improves routing performance while constraining all recovered tool chains to valid graph paths.

\end{enumerate}
